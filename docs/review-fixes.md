# What changed from the earlier version

| Earlier issue | Now |
|---|---|
| Spring Boot 3.3.1, Java 21 | Spring Boot 4.1.1, Java 25 |
| `spring-ai-openai-spring-boot-starter` (does not exist for 2.x) | Spring AI BOM 2.0.1 + `spring-ai-starter-model-openai` |
| Reflection call to `getContent()` always fell back to mock | Typed `ChatClient` with structured output into `GeneratedFix` |
| Placeholder model name | Real model ids by configuration (`gpt-4o-mini`, `qwen2.5-coder:7b`) |
| PostgreSQL | SQL Server 2022 with Flyway SQL Server migrations |
| `pg_advisory_xact_lock` | `sp_getapplock` |
| Audit rows could be updated or deleted; demo reset wiped audit | Triggers block UPDATE/DELETE, login denied; nothing deletes audit |
| Hash over `|`-joined fields | Length-prefixed canonical encoding |
| Prompt stored as "Triage finding 1" | Full system and user prompt, raw output, tokens and latency stored; digests chained |
| Hardcoded patch and PR text | Generated by the model (or rule-based fallback marked as such) and validated |
| No planner | Weighted priority score with explainable breakdown |
| Everything waited for approval | Deterministic LOW / MEDIUM / HIGH routing |
| Fake PR URL and ticket id | Real GitHub and Jira calls, or DRY_RUN with no link |
| Approver taken from request body | Approver is the authenticated principal |
| API key sent in two headers | Spring AI client sends the provider's own header |
| Random mock embeddings | Real embeddings, or BM25 keyword ranking |
| Hardcoded 10/25/6 → "40%" | Computed from stored CI runs; reduction shown only with enough data on both sides |
| No retries or idempotency | Backoff with jitter, idempotency keys, duplicate CI runs ignored |
| `@CrossOrigin("*")`, open actuator, plain passwords in YAML | CORS allow-list, actuator for ADMIN, secrets from environment / Key Vault |
| `Set-Content -Encoding utf8` BOM breaks `javac` on PowerShell 5.1 | Scripts write UTF-8 without BOM; no generator scripts needed |
| npm `"latest"` | Exact pinned versions with lock file |
